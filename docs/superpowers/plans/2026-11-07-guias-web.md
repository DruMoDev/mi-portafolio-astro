# Guías en drumorera.com (parte web) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sección `/guias` en drumorera.com con muro de email suave, base de leads propia con historial de guías vistas, bloque de servicio y despliegue automático, lista para recibir las guías migradas.

**Architecture:** Las guías son Markdown en una colección de Astro (build-time). Un plugin rehype parte cada guía en pasos (`<section>` por `##`), envuelve la parte cerrada en `.guia-cerrada` y marca los bloques copiables; la página reproduce la variante A del prototipo. El muro es CSS + un script ligero; los leads van a una D1 propia (`LEADS`) por `/api/lead`, con la lógica en un handler puro testeado con un almacén falso, igual que `contact-handler`.

**Tech Stack:** Astro 5.17, Tailwind 4 (y CSS propio por componente, como el resto de la web), TypeScript, Vitest, Cloudflare Workers + D1, Workers Builds.

**Spec:** `docs/superpowers/specs/2026-11-07-guias-design.md`. **Referencia visual obligatoria:** `docs/superpowers/prototypes/2026-11-07-guias.html`, variante **A · Recorrido** y vista **Índice /guias** (ábrelo en el navegador; la implementación copia su maquetación, tiempos, curvas y textos).

**Fuera de este plan** (planes propios, después de que este esté en producción, porque dependen del esquema y las URLs que define): (2) migración de las 13 guías de Notion + avisos en Notion + cambio de enlaces en tiktok-editor; (3) skill de publicación en tiktok-editor.

## Global Constraints

- Astro 5.17 sin actualizar a 6; sin frameworks de UI ni librerías de animación; scripts en vanilla TS dentro de los componentes.
- Dependencias nuevas: solo `satori` y `@resvg/resvg-js` (Task 6, imágenes OG en build). Ninguna más.
- Español; sin rayas largas (—) en ningún texto visible ni en los commits.
- Tipografía Geist (ya en el repo); tokens del prototipo: `--ink #000`, `--soft #6E6E73`, `--line #E6E6EA`, `--tint #F4F5F8`, `--accent #2440FF`, `--ok #0E7A57`, `--ease cubic-bezier(.7,0,.2,1)`, `--spring cubic-bezier(.2,.9,.3,1.3)`, `--out cubic-bezier(.16,1,.3,1)`. Reutiliza los que ya existan en `src/styles/global.css`.
- Animaciones por bloques, nunca atadas al scroll palabra a palabra; `prefers-reduced-motion` las deja instantáneas. Foco visible, contraste AA, teclado.
- La guía entera va en el HTML. El difuminado solo existe con JS (`html.js`); sin JS se lee todo.
- Base de leads separada (`LEADS`, D1 nueva `dru-web-leads`), nada en la D1 de DForge. Nunca se manda el email a PostHog ni a terceros.
- CI verde: `npm run format:check && npm run type-check && npm run test && npm run build`.
- Commits con `git add` de rutas explícitas; sin firmas de IA en commits.

## Review Focus

1. **El mismo email con otra forma** (`Ana@Gmail.com `, desde el móvil otro día): se une al mismo lead, no crea otro. → test en Task 4 (`normaliza y reutiliza el lead`).
2. **La API de leads falla o tarda** (D1 caída, 5xx, sin red): la guía se desbloquea igual y el visitante no ve un error técnico; el lead se pierde y se registra en consola. → test en Task 4 (`unlockGuide desbloquea aunque la API falle`).
3. **`localStorage` no disponible** (Safari privado, bloqueado): desbloquear funciona en esa visita; no hay excepción. → test en Task 3 (`storage que lanza`).
4. **Guía sin `##` o con `gateAfter` mayor que sus pasos**: se renderiza sin muro y sin romper el build. → test en Task 1 (`sin pasos suficientes no hay parte cerrada`).
5. **Id guardado que el servidor no conoce** (base reiniciada, id manipulado): `/api/lead/visita` responde 404, el cliente borra el id y la próxima guía vuelve a pedir el email. → tests en Task 4.

  ```ts
  export interface LeadStore {
    upsertLead(l: {
      email: string;
      guide: string;
      consentVersion: string;
      consentText: string;
      utmSource: string | null;
      utmMedium: string | null;

  export function handleVisit(
    req: Request,
    deps: { store?: LeadStore; now: () => number }
  ): Promise<Response>;
  ```
  `POST /api/lead` body `{ email, guide, consent: true, utm?: { source, medium, campaign }, website?: "" }` → `200 { ok: true, id }`; email normalizado (`trim().toLowerCase()`); `consent !== true` → 400; campo trampa `website` relleno → `200 { ok: true, id: <uuid falso> }` sin guardar; límite 10 por IP cada 10 min → 429; sin `store` en dev → id falso y log; sin `store` fuera de dev → 503.
  `POST /api/lead/visita` body `{ id, guide }` → `204` si existe, `404` si no.
- Tablas (`0001_leads.sql`):
  - `leads(id TEXT PRIMARY KEY, email TEXT NOT NULL UNIQUE, created_at INTEGER NOT NULL, consent_version TEXT NOT NULL, consent_text TEXT NOT NULL, first_guide TEXT NOT NULL, utm_source TEXT, utm_medium TEXT, utm_campaign TEXT)`
  - `visitas(lead_id TEXT NOT NULL REFERENCES leads(id), guide TEXT NOT NULL, first_at INTEGER NOT NULL, last_at INTEGER NOT NULL, count INTEGER NOT NULL DEFAULT 1, PRIMARY KEY (lead_id, guide))`
